# 文件放哪、怎么删

## 放在哪

| 文件 | 位置 | 原因 |
|------|------|------|
| 不该公开的资料：研究对象的名单和名字（第三方的游戏、作者、站点）、从别人那里下载的文件、账号和个人数据 | 被 Git 忽略的本地目录，项目有就用它（比如 `.local/`）；即使它是脚本产物或中间结果，也放这里 | 仓库可能是公开的，推送后就算删掉文件，旧提交里也还留着 |
| 只在这一轮用的中间文件 | 会话的 scratchpad，没有时用系统临时目录 | 用完即弃，不该留在项目里 |
| 这项任务的中间结果、下载物、备份 | `.tmp/<任务名>/`，下载物放它的 `downloads/` | 会话结束或上下文压缩后，你和用户都还找得到 |
| 一次性维护脚本 | `scripts/`，产物放 `scripts/out/<脚本名>/` | 和项目代码分开，又能被找到 |
| 要交付或纳入版本控制的产物 | 项目里对应的目录，即使由脚本生成 | 它是结果，不是中间物 |

- 入库的文档、注释、测试和 commit message 只写通用描述，测试用占位名；提交前用 `git grep -i <名字>` 查一遍已跟踪的文件，commit message 也看一眼
- 长时间收集的资料，边收集边写进 `.tmp/<任务名>/`，以免会话中断或上下文压缩后丢失
- 往 `.tmp/` 或 `.trash/` 写之前，用 `git check-ignore -q .tmp/x` 确认它被忽略（退出码 0 表示已忽略）；没有的话写进 `.git/info/exclude`，不为这个改项目的 `.gitignore`。自己新建的仓库直接写进 `.gitignore`
- 生成物的名字带上来源脚本和用途：`thumbnail-resize.py` 生成 `thumbnail-resize__batch01.png`

## 删除或替换

先确认准确的目标，再看 Git 状态：

| 目标 | 做法 |
|------|------|
| 可重新生成的构建产物、依赖、缓存、临时文件 | 直接删 |
| 已跟踪、当前版本已提交 | 直接改或删，Git 能恢复 |
| 已跟踪、有未提交修改 | 先 `git diff HEAD --output=.tmp/<任务名>/<文件名>.patch -- <文件>`，并说出备份位置；操作涉及整个工作区时才用 `git stash -u` |
| 有恢复价值的未跟踪文件，尤其是用户建的 | 移到 `.trash/<日期>/<原相对路径>`，保留原路径以免同名文件互相覆盖 |
| 凭据、密钥、个人数据 | 不复制进 `.trash/`，删除或保留前先问 |
