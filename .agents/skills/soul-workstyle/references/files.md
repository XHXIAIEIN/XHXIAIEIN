# Where files go, how they are deleted

## Where

| File | Place | Why |
|------|-------|-----|
| Material that must not be public: lists and names of studied subjects (third-party games, authors, sites), files downloaded from others, accounts and personal data | A Git-ignored local folder, the project's own if it has one (such as `.local/`); even when it is a script's output or an intermediate result | The repository may be public; a file deleted after a push still lives in old commits |
| Intermediate files used only this turn | The session's scratchpad, or the system temp folder when there is none | Thrown away after use; they do not belong in the project |
| A task's intermediate results, downloads and backups inside a repository | `.tmp/<task>/`, downloads under its `downloads/` | You and the user can still find them after the session ends or the context is compressed |
| Probes, repro projects and other generated work outside a repository | An intent folder, see "Generated work" below | The user looks for output beside the script that made it |
| One-off maintenance scripts | `scripts/`, output under `scripts/out/<script>/` | Kept apart from project code, yet findable |
| Products to deliver or put under version control | The matching folder in the project, even when generated by a script | It is a result, not an intermediate |

- Committed docs, comments, tests and commit messages use generic descriptions only, and tests use placeholder
  names; before committing, run `git grep -i <name>` over tracked files and read the commit message
- A finding from someone else's project or screenshots goes into the repository as the mechanism: no project,
  object or variable names, no story of how it came up; the concrete case stays in the conversation or the ignored
  folder
- Material collected over a long time is written into `.tmp/<task>/` as it is collected, so it survives an
  interrupted session or a compressed context
- Before writing into `.tmp/` or `.trash/`, confirm it is ignored with `git check-ignore -q .tmp/x` (exit code 0 means
  ignored); if not, add it to `.git/info/exclude` rather than changing the project's `.gitignore`. In a repository you
  created yourself, add it to `.gitignore`
- A generated file's name carries its source script and purpose: `thumbnail-resize.py` makes
  `thumbnail-resize__batch01.png`
- Generated or converted media default to WebP for images and WebM (VP9 or AV1 video, Opus audio), unless the
  target cannot play them or the user names another format; SVG icons and canvas textures made in code are exempt
- Output that gets regenerated (a summary, a cache, an index, a generated file) is fixed at its generator or its
  rule; an edit to the output is lost on the next run

## Generated work

Generated work outside a repository goes in one folder per intent in the scratchpad, named for what the task is for
(`pitfalls-revalidation/`), split in two:

- `final/`: what the task delivers, one folder each with its generator script beside it
  (`final/fill-poly-repeated-point/`: the project, its .zip, `mk_fillpoly_repro.py`)
- `process/`: what was made on the way, each with its own script beside it: probes, controls, preview plans,
  screenshots, results, sweeps, a project opened only to show the user

A generator writes beside itself by default (`Path(__file__).parent`), never to a path passed by hand such as
`%TEMP%\out`. The user looks for output next to the script that made it and must tell the deliverable from the
by-products at a glance.

## Agent tooling: hooks, agents, skills, memory

Ask whether the thing depends on the repository's files. If not, it is the user's: put it under `~/.claude/`
(sub-agents in `agents/`, skills in `skills/`, cross-project memory in `memory/`, hooks in `settings.json`). If it
does, put client-neutral scripts in the repository's `.agents/` and only the Claude-only registration in `.claude/`
(Claude Code loads sub-agents only from `.claude/agents/`, skills only from `.claude/skills/`). A habit the user
holds across projects, kept in one repository, misses the other projects and pushes their taste onto contributors.

Tooling an agent carries into another project follows the Agent Skills layout (https://agentskills.io): `SKILL.md`
with name and description, `scripts/`, `references/`, `assets/`; scripts with `--help`, no interactive prompts,
errors that say what to do; SKILL.md under 500 lines. The entry documents tell an arriving agent to install it
itself, so the user does not carry files by hand. Check each client's discovery folder before claiming it works:
Claude Code `.claude/skills/`, TRAE `.trae/skills/`, most others `.agents/skills/`.

A tool you build writes only inside the project it serves: no dotfile, config folder or environment variable in the
user's home. When a later session must find something again (where a clone lives), the tool prints it and tells the
agent to remember it; the agent's memory is the place for it, and the user's directories are theirs. A default
location is a filled-in example the user can replace, never a requirement.

A rule that holds in every project and shapes how work is done belongs in these soul skills; machine facts and
narrow procedures (one tracker, one tool) stay in memory.

## Deleting or replacing

Confirm the exact target first, then look at its Git state. Asked to keep what is useful from a set (logs, sessions,
old folders), inspect every item before deleting any; an item not looked at goes to `.trash/`, not away.

| Target | Do |
|--------|----|
| Build output, dependencies, caches, temp files that can be regenerated | Delete |
| Tracked, current version committed | Change or delete; Git can restore it |
| Tracked, with uncommitted changes | First `git diff HEAD --output=.tmp/<task>/<file>.patch -- <file>` and say where the backup is; `git stash -u` only when the operation covers the whole working tree |
| Untracked with recovery value, especially the user's own | Move to `.trash/<date>/<original relative path>`, keeping the path so same-named files do not overwrite each other |
| Credentials, keys, personal data | Do not copy into `.trash/`; ask before deleting or keeping |
