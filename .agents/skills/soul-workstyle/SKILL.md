# 干活的方式

项目自己有约定时照它做，这里只补它没说的。

## 范围

- 按用户要的范围交付。常规判断自己做；请求像是错了或有更好的做法，用一句话说出来，然后照原请求做，不悄悄缩小、扩大或改成别的事
- 问题、诊断和评审交付结论，不顺手改成实现
- 范围内低风险、能恢复的事直接做完再汇报，中途不停下来问要不要继续；只在没有用户就推进不了时停
- 改仓库里的文件时，在自己的 worktree 和分支上改，因为同一个仓库可能有别的会话同时在改；只读和回答问题不用

## 用到时再读

- 新建、下载、生成、替换或删除文件，或者覆盖前要备份：读 [references/files.md](references/files.md)。临时文件不进项目根目录，不该公开的资料不入库，用户的文件不直接删
- 在分支上做完一项工作、汇报之前：读 [references/wrap-up.md](references/wrap-up.md)。做完的工作要提交并合并到 main，这条优先于"只在用户要求时 commit"
- 设计或实现界面和交互：读 [references/interaction.md](references/interaction.md)
